# MySQL 0817 上課重點筆記

索引・新增・修改・刪除・交易控制

依 5 份課堂 SQL 檔整合｜附簡單說明與錯誤修正

> [!note] 先記住
> 今天的內容可分成兩大類：DDL 用來定義表格與索引；DML 用來新增、修改、刪除資料。交易控制則決定異動是否正式保存。

## 1. 指令分類快速表

| 分類 | 用途 | 今天出現的指令 |
| --- | --- | --- |
| DDL（資料定義） | 建立或修改資料庫物件的結構 | CREATE、ALTER、DROP、TRUNCATE |
| DML（資料操作） | 新增、修改、刪除資料列 | INSERT、UPDATE、DELETE、REPLACE |
| TCL（交易控制） | 確認或取消一批資料異動 | START TRANSACTION、COMMIT、ROLLBACK |
| DQL（資料查詢） | 讀取與檢查資料 | SELECT、DESC、SHOW INDEX |

> [!note] 備註
> 課堂註解將 START TRANSACTION 寫成 DCL；較精確的分類是 TCL（Transaction Control Language）。

## 2. 索引（Index）

| 種類 | 限制／特性 | 適合用途 |
| --- | --- | --- |
| PRIMARY KEY | 值唯一、不可為 NULL；每張表只有一組主鍵，可由多欄組成 | 識別每一筆資料，例如 id |
| UNIQUE KEY | 非 NULL 值不可重複；MySQL 通常允許多筆 NULL | email 等需要唯一、但可暫時不填的資料 |
| INDEX / KEY | 可重複、可為 NULL；主要用於加速查詢 | 常用搜尋、排序、JOIN 的欄位 |
| FOREIGN KEY | 限制子表值必須對應父表的候選鍵，並自動需要索引支援 | 建立表與表之間的參照完整性 |

> [!note] 重要修正
> FOREIGN KEY 不是「一般索引」本身，而是一種參照限制；MySQL 會要求相關欄位具有可用索引。

### 2.1 建表時建立索引

```sql
CREATE TABLE IF NOT EXISTS test2 (
    id INT,
    name VARCHAR(30),
    countrycode CHAR(30),
    district CHAR(30),
    population INT,
    UNIQUE KEY (district),
    INDEX (countrycode),
    PRIMARY KEY (id, name(5))
);
```

- PRIMARY KEY (id, name(5)) 是複合主鍵，並只取 name 前 5 個字元建立索引。

- 前綴索引 name(5) 可減少索引大小，但前 5 個字元仍必須能區分資料，否則可能出現重複鍵。

### 2.2 建表後新增索引

```sql
ALTER TABLE address1 ADD PRIMARY KEY (id);
ALTER TABLE address1 ADD UNIQUE KEY (email);
ALTER TABLE address1 ADD INDEX (name, tel);
ALTER TABLE address1 ADD INDEX (address(5));

CREATE UNIQUE INDEX email_index ON address2(email);
CREATE INDEX name_tel_index ON address2(name, tel);
```

> [!note] 複合索引
> INDEX(name, tel) 通常可支援只用 name 的查詢，也可支援同時用 name 與 tel 的查詢；單獨只查 tel 時未必能有效使用，這稱為最左前綴原則。

### 2.3 查看與刪除索引

```sql
DESC db2.address1;
SHOW INDEX FROM db2.address1;

ALTER TABLE address2 DROP INDEX name_tel_index;
DROP INDEX email_index ON address2;
ALTER TABLE address2 DROP PRIMARY KEY;
```

> [!note] 注意
> 刪除主鍵建議使用 ALTER TABLE ... DROP PRIMARY KEY；不要寫 DROP INDEX `PRIMARY` ON ...，因為主鍵不是一般索引的刪除語法。

### 2.4 AUTO_INCREMENT 與 SERIAL

```sql
CREATE TABLE test100 (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(20)
);

-- MySQL 中 SERIAL 是 BIGINT UNSIGNED NOT NULL AUTO_INCREMENT UNIQUE 的別名
CREATE TABLE test101 (
    id SERIAL,
    name VARCHAR(20)
);
```

> [!note] 修正
> 原檔連續建立兩次 test100，且第一段後面少分號。若要保留兩個版本，應改用不同表名，或先 DROP TABLE。

## 3. INSERT 新增資料

### 3.1 常見寫法

```sql
INSERT INTO cmdev.dept (deptno, dname, location)
VALUES (100, 'abcdef', 'taoyuan');

INSERT INTO cmdev.dept
VALUES (200, 'abcdef', 'taoyuan');

INSERT INTO cmdev.dept (dname, deptno, location)
VALUES ('abcdef', 300, 'taoyuan');
```

- 有指定欄位名稱時，VALUES 的值必須依指定欄位順序對應。

- 省略欄位名稱時，值的數量與順序必須完全符合資料表定義；維護性較差，建議明確列出欄位。

### 3.2 NULL、DEFAULT 與空字串

| 寫法 | 實際意義 |
| --- | --- |
| location = NULL | 沒有值／未知值 |
| 省略 location | 使用欄位預設值；沒有明確 DEFAULT 時通常為 NULL（前提是允許 NULL） |
| location = DEFAULT | 明確要求使用欄位預設值 |
| location = '' | 有值，但內容是長度為 0 的空字串；不等於 NULL |

```sql
INSERT INTO cmdev.dept (deptno, dname, location) VALUES (400, 'RD', NULL);
INSERT INTO cmdev.dept (deptno, dname) VALUES (401, 'RD2');
INSERT INTO cmdev.dept (deptno, dname, location) VALUES (402, 'RD', DEFAULT);
INSERT INTO cmdev.dept (deptno, dname, location) VALUES (403, 'RD4', '');
```

### 3.3 一次新增多筆

```sql
INSERT INTO cmdev.dept (deptno, dname, location) VALUES
    (405, 'RD4', ''),
    (406, 'RD4', ''),
    (407, 'RD4', ''),
    (408, 'RD4', '');
```

## 4. 遇到重複鍵時怎麼處理

| 語法 | 重複鍵時的行為 | 適用情境 |
| --- | --- | --- |
| 普通 INSERT | 產生錯誤，該筆不新增 | 希望嚴格發現資料問題 |
| INSERT IGNORE | 略過衝突資料並回傳警告 | 衝突時不要中斷程式 |
| INSERT ... ON DUPLICATE KEY UPDATE | 改為更新指定欄位 | 計數器、upsert |
| REPLACE | 刪除舊列後插入新列；未提供欄位可能回預設值 | 確定接受刪除再新增的副作用 |

```sql
INSERT IGNORE INTO cmdev.dept (deptno, dname, location)
VALUES (400, 'RD', NULL);

INSERT INTO cmdev.travel VALUES (7369, 'chicago', 1)
ON DUPLICATE KEY UPDATE counter = counter + 1;

REPLACE INTO cmdev.travel
SET empno = 7369, location = 'boston', counter = 1;
```

> [!note] 考試重點
> ON DUPLICATE KEY UPDATE 是新增或更新同一筆資料的常用做法。REPLACE 並不是普通 UPDATE，而可能觸發 DELETE + INSERT，因此自動編號、外鍵及觸發器行為都可能不同。

## 5. UPDATE 修改資料

```sql
UPDATE cmdev.emp
SET salary = salary + 1
WHERE salary <= 1000;

UPDATE cmdev.emp
SET salary = salary + 3
ORDER BY salary ASC
LIMIT 3;
```

- WHERE 決定哪些列要修改；若沒有 WHERE，可能修改整張表。

- ORDER BY ... LIMIT 可限制只修改排序後的前幾筆；結果相同時最好再加入唯一欄位排序，讓結果可預期。

### 5.1 UPDATE IGNORE

```sql
UPDATE IGNORE cmdev.emp
SET empno = 7369
WHERE empno = 7900;
```

> [!note] 注意
> IGNORE 可能把部分錯誤降為警告或略過衝突列，容易掩蓋資料品質問題。執行後應用 SHOW WARNINGS 檢查警告。

```sql
-- 錯誤寫法：SET 中不能用 AND 串接欄位指定
UPDATE IGNORE cmdev.travel
SET empno = 7369 AND location = 'BOSTON', counter = 10
WHERE empno = 7359 AND location = 'boston';

-- 正確寫法：SET 欄位之間用逗號，WHERE 條件之間用 AND
UPDATE cmdev.travel
SET empno = 7369, location = 'BOSTON', counter = 10
WHERE empno = 7359 AND location = 'boston';
```

## 6. DELETE 與 TRUNCATE

```sql
DELETE FROM cmdev.travel
WHERE empno = 7359;

DELETE FROM cmdev.travel
ORDER BY counter DESC
LIMIT 1;

TRUNCATE TABLE cmdev.travel;
```

| 比較 | DELETE | TRUNCATE |
| --- | --- | --- |
| 刪除範圍 | 可用 WHERE 刪除部分或全部資料 | 一次清空整張表 |
| 類型 | DML | DDL |
| 速度與記錄 | 逐列處理，通常較慢 | 通常較快，重建／重置表的儲存結構 |
| 交易回復 | InnoDB 交易內通常可 ROLLBACK | MySQL 會隱含 COMMIT，通常不能 ROLLBACK |
| AUTO_INCREMENT | 通常不重設 | 通常重設 |

> [!note] 重要修正
> 原檔示範 START TRANSACTION → TRUNCATE → ROLLBACK，但 MySQL 的 TRUNCATE TABLE 會造成隱含提交，ROLLBACK 無法恢復被清空的資料。

## 7. 交易控制（Transaction）

```sql
START TRANSACTION;

DELETE FROM cmdev.travel
WHERE empno = 7521 AND location = 'DALLAS';

SELECT * FROM cmdev.travel;  -- 先檢查結果
ROLLBACK;                    -- 取消本次交易

START TRANSACTION;
UPDATE cmdev.travel
SET counter = 100
WHERE empno = 7521 AND location = 'DALLAS';
COMMIT;                      -- 正式保存，之後不能用 ROLLBACK 取消
```

| 指令 | 意義 |
| --- | --- |
| START TRANSACTION | 開始一個交易範圍 |
| COMMIT | 永久保存本交易的異動 |
| ROLLBACK | 取消尚未 COMMIT 的異動 |

> [!note] 使用條件
> 交易回復主要適用於 InnoDB 等支援交易的儲存引擎。DDL 常會隱含 COMMIT，因此不要把 CREATE、ALTER、DROP、TRUNCATE 當成可安全回滾的普通 DML。

## 8. 課堂練習表整理

### 8.1 pet 與 event

```sql
USE mylab;

CREATE TABLE IF NOT EXISTS pet (
    id SERIAL COMMENT '寵物編號',
    name VARCHAR(30) NOT NULL COMMENT '寵物名稱',
    owner VARCHAR(30) NULL COMMENT '主人名稱',
    species VARCHAR(30) NULL COMMENT '寵物類別',
    gender ENUM('m','f') COMMENT '寵物性別',
    birth DATE NULL COMMENT '出生日期',
    PRIMARY KEY (id)
);

CREATE TABLE IF NOT EXISTS event (
    id BIGINT UNSIGNED NOT NULL COMMENT '寵物編號',
    edate DATE NOT NULL COMMENT '日期',
    etype VARCHAR(15) NOT NULL COMMENT '種類',
    remark VARCHAR(255) NULL COMMENT '說明'
);
```

- NOT NULL 表示一定要有值；NULL 表示允許沒有值。

- ENUM('m','f') 只允許指定的選項，適合固定且很少變動的值。

> [!note] 設計提醒
> SERIAL 已包含 UNIQUE，但若 id 要當正式主鍵，仍可明確宣告 PRIMARY KEY。event.id 若代表 pet.id，較完整的設計可增加 FOREIGN KEY，並依需求設計 event 自己的主鍵。

### 8.2 建立練習資料與索引

```sql
ALTER TABLE mylab.pet ADD INDEX pet_name_index (name);
CREATE INDEX pet_owner_index ON mylab.pet(owner);
SHOW INDEX FROM mylab.pet;

CREATE TABLE cmdev.myemp (
    id INT NOT NULL PRIMARY KEY,
    firstname VARCHAR(25) NOT NULL,
    lastname VARCHAR(25) NOT NULL,
    salary INT,
    birthdate DATE
);

INSERT INTO cmdev.myemp VALUES
    (1, 'Betty', 'Johnson', 1200, '1968-01-06'),
    (2, 'Sam',   'Johnson',  900, '1972-09-12'),
    (3, 'Rose',  'Johnson', 1100, '1971-11-06');
```

## 9. 執行前安全檢查

- 先用 SELECT + 相同 WHERE 確認會影響哪些資料。

- 重要 UPDATE／DELETE 先 START TRANSACTION，檢查後再 COMMIT；有問題就 ROLLBACK。

- 確認 WHERE 中的主鍵或唯一鍵是否寫對，避免整表異動。

- 使用 INSERT IGNORE／UPDATE IGNORE 後執行 SHOW WARNINGS。

- 避免以 TRUNCATE 測試交易回復，因為 MySQL 通常無法回滾。

## 10. 今日必背語法

```sql
-- 查看結構與索引
DESC table_name;
SHOW INDEX FROM table_name;

-- 新增索引／刪除索引
ALTER TABLE table_name ADD INDEX index_name (column_name);
ALTER TABLE table_name DROP INDEX index_name;
ALTER TABLE table_name DROP PRIMARY KEY;

-- 新增／重複鍵更新
INSERT INTO table_name (col1, col2) VALUES (val1, val2);
INSERT INTO table_name (col1, col2) VALUES (val1, val2)
ON DUPLICATE KEY UPDATE col2 = VALUES(col2);

-- 安全修改／刪除
START TRANSACTION;
UPDATE table_name SET col1 = value WHERE primary_key = value;
DELETE FROM table_name WHERE primary_key = value;
COMMIT;  -- 或 ROLLBACK;
```
